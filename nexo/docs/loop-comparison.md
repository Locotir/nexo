# Recurring prompts: Nexo, Claude Code and Grok Build

Comparison checked 2026-11-24. Nexo describes the inspected working tree, not necessarily a released version. External entries describe official documentation, not independent runtime observations; features and versions can change. This is about `/loop`, not cloud or desktop schedulers.

| Aspect | Nexo (local code) | Claude Code ([official docs][claude]) | Grok Build ([official repository guide][grok]) |
|---|---|---|---|
| Invocation | `/loop <interval> <prompt>`; interval and prompt required. Model can also request create/list/cancel through the `loop` tool. | `/loop [interval] [prompt]`: missing interval is dynamically chosen; missing prompt uses maintenance instructions or `loop.md`. Natural-language scheduling is also supported. | `/loop [interval] <prompt>`; the guide does not specify the default interval. Lower-level scheduler tools are also documented. |
| Timing | 60 seconds–30 days, integer `s`, `m`, `h`, `d`; first run when idle, then due interval measured from admission. Busy/held/queued work defers execution. Maximum 8 loops. | Fixed intervals use cron, with minute granularity, rounding and documented jitter; alternatively Claude chooses a delay. Up to 50 scheduled tasks. | 60-second minimum, supports `s`, `m`, `h`, `d`; prompt fires immediately and repeats. Up to 50 active scheduled tasks. |
| Execution context | Scheduled prompt starts a turn in the current session; no overlap with another turn. | Scheduled prompt runs between turns; if busy it waits. | Each fire runs in a detached background subagent that cannot see the conversation; the stored prompt must stand alone. |
| Lifetime and stopping | Session-local, not persisted; closing or switching sessions stops loops. `/loop list`, `/loop cancel <id>`; cancelling does not stop an already running turn. Failures/interruption pause a loop; only the person can resume it. | Session-scoped; unexpired tasks can be restored on resume, subject to documented exceptions. Ask Claude to list/cancel fixed tasks; self-paced loops also have keyboard stop controls. The linked page documents seven-day expiry. | Recurring tasks expire after seven days. Scheduler list/delete manage tasks; the lower-level API has a `durable` option defaulting to false. The guide does not establish whether `/loop` itself sets it. |
| Permissions | Submit hooks run before admission; a blocking hook pauses the loop. Future tool calls require their own permissions. | `/loop` inherits session permission prompts; the maintenance prompt passes permission checks. | The cited loop guide does not establish the permission policy for each detached fire; unknown here. |

Local evidence: [`scheduled.rs`](../crates/nexo-agent/src/turn/scheduled.rs), [`control_tool.rs`](../crates/nexo-agent/src/turn/control_tool.rs), and simulated-agent tests for [scheduled turns](../crates/nexo-agent/tests/agent_loop/scheduled_loop.rs) and [model control](../crates/nexo-agent/tests/agent_loop/control_tools.rs). These establish implementation and test coverage, not a live end-to-end proof of repeated cycles. No live Claude Code or Grok Build run was performed for this comparison. In particular, an immediate first Nexo run in a simulated session is not evidence that a second timed cycle ran against a real provider.
